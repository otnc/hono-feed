## Conventions

- **Formatting and linting is Biome** (`biome.json`) — single quotes, no semicolons, trailing commas, 100-column width. Running `pnpm check` before you commit handles all of it.
- **Tests live next to the code** as `*.test.ts` and run with vitest.
- **Code comments are in English** and kept brief.
- **User-facing docs are bilingual (English and Japanese).** `README.md`, `CONTRIBUTING.md` and `HONOFEED_DEP.md` (and their `*.ja.md` counterparts) are generated by [Kiritan](https://github.com/otnc/kiritan) from `base/*.base.md`. Edit the base file, never the generated ones, then run `pnpm build:docs`. Put English and Japanese side by side in small `:::kiritan{locale=en}` / `:::kiritan{locale=ja}` pairs, one per section, and keep anything language-neutral (code blocks, badges) outside the blocks.
- **No runtime dependencies.** `hono` is a peer dependency, and everything else uses Web Standard APIs only (`Response`, `URL`, `TextEncoder`, …) so the package keeps running on every edge runtime — `platform: 'neutral'` in the build enforces this. If a Node-only API is genuinely worth it (like `process.emitWarning`), feature-detect it through `globalThis` and fall back gracefully; `src/utils/deprecation.ts` is the example to follow.
- **Type-only imports use `import type`** (`verbatimModuleSyntax` is on).

## Adding a feed version

Every supported version value is a typed union in `src/types.ts`, which keeps invalid versions from ever reaching a serializer. To add one:

1. Add the value to the relevant union in `src/types.ts`.
2. Implement it — add a per-version file under `src/formats/{rss,atom}/` and wire it into that format's `index.ts` dispatcher. If the variant only changes the `version` attribute (as RSS 0.9x does), extend the shared serializer instead of writing a new file — see `rss2.ts`.
3. Keep the serializers pure. When a required identity is missing (an Atom or RDF `id`), throw a `TypeError` rather than emitting a broken document.
4. Update the version tables in `base/README.base.md` and add a test.

If you're **deprecating** a version, call `warnDeprecated(key, message, code)` from `src/utils/deprecation.ts` in that format's `index.ts`, guarded by `!opts.suppressDeprecationWarnings`. It fires once per process, tags the warning with a stable code, and respects the usual mute switches. Assign the next `HONOFEED_DEP00NN` code and add a row to [HONOFEED_DEP.md](HONOFEED_DEP.md) (edit `base/HONOFEED_DEP.base.md`).

## Pull requests

Keep each change focused and add tests for any new behaviour. When something is about spec-compliance — a date format, escaping rule, or HTTP detail — a line explaining it in the PR goes a long way, since correctness is the whole point of this library.

## Releasing (maintainers)

Releasing is one manual step. From the Actions tab, run the `release` workflow (`workflow_dispatch`) and give it a `version` input — either a bump keyword (`patch` / `minor` / `major` / `prerelease`) or an explicit version like `0.2.0`. The workflow runs the checks and build, bumps `package.json`, publishes to npm with provenance, regenerates `CHANGELOG.md` with [git-cliff](https://git-cliff.org) (`cliff.toml`), pushes the version commit and tag, and creates a GitHub Release whose notes are the new changelog section. The changelog is built from [Conventional Commits](https://www.conventionalcommits.org) — `feat`, `fix`, `perf`, `refactor` and `docs` are listed, everything else is left out — so write commit messages in that form, and don't edit `CHANGELOG.md` by hand. It needs an `NPM_TOKEN` secret and write access for the default `GITHUB_TOKEN`.

## 規約

- **フォーマットとリントは Biome** (`biome.json`)です。シングルクォート、セミコロンなし、末尾カンマ、100 桁幅に統一しています。コミット前に `pnpm check` を実行すれば、すべて整います。
- **テストはコードの隣に置きます。** `*.test.ts` という名前で、vitest で実行します。
- **コードのコメントは英語で書き**、簡潔にします。
- **利用者向けのドキュメントは日英の 2 言語です。** `README.md`、`CONTRIBUTING.md`、`HONOFEED_DEP.md` と、それぞれの `*.ja.md` は、[Kiritan](https://github.com/otnc/kiritan) が `base/*.base.md` から生成します。編集するのは base ファイルで、生成されたファイルは直接編集せず、`pnpm build:docs` を実行してください。英語と日本語は、セクションごとの小さな `:::kiritan{locale=en}` / `:::kiritan{locale=ja}` のペアとして並べて書き、言語に依存しないもの (コードブロックやバッジ)はブロックの外に置きます。
- **実行時の依存はありません。** `hono` は peer dependency で、それ以外は Web 標準 API だけを使います (`Response`、`URL`、`TextEncoder` など)。これにより、すべてのエッジランタイムで動き続けます。ビルドの `platform: 'neutral'` が、これを強制しています。Node 専用の API を使う価値が本当にある場合 (`process.emitWarning` など)は、`globalThis` 経由で機能を検出し、使えなければ穏当にフォールバックしてください。手本は `src/utils/deprecation.ts` です。
- **型だけの import には `import type` を使います** (`verbatimModuleSyntax` を有効にしています)。

## フィードのバージョンを追加する

サポートするバージョンの値は、すべて `src/types.ts` の型付きユニオンで定義しています。そのため、不正なバージョンがシリアライザーに届くことはありません。追加する手順は次のとおりです。

1. `src/types.ts` の該当するユニオンに値を追加します。
2. 実装します。`src/formats/{rss,atom}/` にバージョンごとのファイルを追加し、そのフォーマットの `index.ts` のディスパッチャーにつなぎます。RSS 0.9x のように `version` 属性だけが変わるバリエーションなら、新しいファイルを書かずに共通のシリアライザーを拡張してください。`rss2.ts` を参照してください。
3. シリアライザーは副作用のない形に保ちます。必須の識別子 (Atom や RDF の `id`)がない場合は、壊れたドキュメントを出力せず、`TypeError` を投げます。
4. `base/README.base.md` のバージョン表を更新し、テストを追加します。

バージョンを**非推奨**にする場合は、そのフォーマットの `index.ts` で、`src/utils/deprecation.ts` の `warnDeprecated(key, message, code)` を、`!opts.suppressDeprecationWarnings` で守った上で呼び出します。警告はプロセスごとに 1 回だけ出て、固定のコードが付き、通常の抑制スイッチにも従います。次の `HONOFEED_DEP00NN` コードを割り当て、[HONOFEED_DEP.ja.md](HONOFEED_DEP.ja.md) に行を追加します (編集するのは `base/HONOFEED_DEP.base.md` です)。

## Pull Request

1 つの変更は焦点を絞り、新しい挙動にはテストを追加してください。日付形式、エスケープ規則、HTTP の細部のような仕様への準拠にかかわる変更では、その理由を PR に一言添えてもらえると大いに助かります。このライブラリでは、正確さがすべてだからです。

## リリース (メンテナー向け)

リリースの手作業は 1 つだけです。Actions タブから `release` ワークフロー (`workflow_dispatch`)を実行し、`version` 入力を渡します。値は、バージョンを上げるキーワード (`patch` / `minor` / `major` / `prerelease`)か、`0.2.0` のような明示的なバージョンです。ワークフローは検査とビルドを実行し、`package.json` のバージョンを更新して、provenance 付きで npm に公開します。その後、[git-cliff](https://git-cliff.org) (`cliff.toml`)で `CHANGELOG.md` を再生成し、バージョンのコミットとタグを push して、新しい changelog の節をノートにした GitHub Release を作成します。changelog は [Conventional Commits](https://www.conventionalcommits.org) から作られます。一覧に載るのは `feat`、`fix`、`perf`、`refactor`、`docs` で、それ以外は載りません。コミットメッセージはこの形式で書き、`CHANGELOG.md` は手で編集しないでください。`NPM_TOKEN` シークレットと、既定の `GITHUB_TOKEN` への書き込み権限が必要です。
